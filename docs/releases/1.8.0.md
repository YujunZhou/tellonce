# Tellonce 1.8.0

This release updates the correction-learning, rule-compilation and rule-checking APIs in the shared core. These are the versions used for the TRACE experiments. The default plugin path for Claude Code, Codex and Copilot keeps the 1.7.1 behavior: background recording stays on by default, explicit opt-out is respected, and hard blocking and the shadow judge remain opt-in.

## Learning from corrections

- A separate interpretation step runs before any library change. It reconstructs what the user is correcting from the reply and the recent exchange, quotes the user's words, and proposes a candidate lesson. That lesson is a hypothesis for the next step, not evidence.
- Admission is stricter about what becomes a rule:
  - An explained error can support a reusable pitfall after one example.
  - A bare replacement, a new task requirement, or an explicit one-time exception is not stored.
  - Concrete names, dates and answers from the example stay in the evidence and are kept out of the rule text.
  - A learned preference is not narrowed to "only if asked again".
- Updates must list every obligation of the rule they replace. Dropping one requires the user's words withdrawing it.
- A new rule must name the closest existing rule and explain the difference. A rule that only adds a new trigger for an existing requirement is turned into an update of that rule.
- A plan that fails local validation gets one repair request that includes the validation error. If the repaired plan also fails, that learning attempt fails.
- In namespaced libraries, transient provider failures and rejected answers get one separate recovery attempt instead of being dropped.

## Compiling rules into checks

- Compilation has four outcomes: deterministic check, semantic check, reminder only, or pending. A pending rule is neither checked nor shown to the agent.
- The reviewer does not see the proposer's expected labels or rationale. It labels each case independently, and any disagreement rejects the proposal.
- Validation cases are preflighted locally before the reviewer is called.
- A repairable rejection is retried with diagnostics for up to three rounds.
- A rule that is left as a reminder or pending is compiled again on the next two publications and again when the library is frozen.
- Review guidance separates applicability from compliance. A case that deliberately lacks the trigger is a valid not-applicable test.

## Checking rules at run time

- Rules that need the same evidence are checked together, at most six per request, and independent groups run in parallel.
- The checker sees a bounded view of recent operations instead of the whole tool-result history.
- Evidence quotes in a verdict must appear in the observation, or they are discarded.
- Each verdict must name the single strongest violation of its own rule. Constraints that belong to other rules are excluded.

## Other changes

- `event_obligations` is a new opt-in module for statements with explicit deadlines. It is not wired into the default plugin or the existing checkers.
- Training freeze, publication repair and learning recovery have dedicated regression checks.

## Compatibility and upgrade

All plugin manifests and marketplaces use 1.8.0. Copilot bootstrap and uninstall instructions point to the immutable v1.8.0 tag; updated bootstrap checksums are listed in both Copilot READMEs. Update through the existing platform installation path and start a new session to load the new package.

Libraries created by earlier versions remain readable. A compiled check from an earlier publication is reused only when its compiler identity matches; otherwise it is compiled again.

## Validation

Before publication, the following passed locally:

- the full `checks` suite on Python 3.9 and 3.12 (393 passed, 1 skipped);
- the unified memory-upsert script (121 tests);
- import checks for every module on Python 3.9;
- cross-variant shared-core parity;
- release metadata and bootstrap checksum validation.

Real-model semantic fixtures are opt-in and were not rerun for this release. Remote CI results are checked after publication.
