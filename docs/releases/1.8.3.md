# Tellonce 1.8.3

This release fixes the order in which queued learning requests are processed. Learning behavior, rule format and the experiment APIs are otherwise unchanged from 1.8.2.

## Queued requests keep their order

- Background learning drains pending requests in filename order. The filename carried a millisecond timestamp, so two requests written within the same millisecond were ordered by their random suffix, and a newer instruction could be processed before an older one. This only happens when requests are queued programmatically in quick succession, such as by an experiment harness; it does not occur with interactive use.
- Filenames now carry a nanosecond timestamp and a per-process sequence number, so requests queued from one process are always processed in the order they were queued. Existing queued files remain readable and sort before new ones.
- A regression check writes two requests under a frozen clock and asserts their order.

## Repository

- `INSTALL.md` and `FAQ.md` moved to `docs/install.md` and `docs/faq.md`; `docs/releases/README.md` indexes the release notes.
- CI runs the Python 3.9 floor on Ubuntu 24.04, since `ubuntu-latest` (Ubuntu 26.04) ships no Python 3.9 build, and reports failed tests as check annotations.

## Compatibility and upgrade

All plugin manifests and marketplaces use 1.8.3. Copilot bootstrap and uninstall instructions point to the immutable v1.8.3 tag, and updated bootstrap checksums are listed in both Copilot READMEs. Update through the existing platform installation path and start a new session to load the new package.

## Validation

Before publication, the full `checks` suite passed on Python 3.9 and 3.12 (400 passed, 1 skipped), along with the unified memory-upsert script, shared-core and Codex skill parity, and release metadata and bootstrap checksum validation. Remote CI results are checked after publication.
